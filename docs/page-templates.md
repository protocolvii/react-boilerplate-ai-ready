# 页面模板

Page Gallery 展示有复用价值的完整页面内容，而非所有业务路由。进入开发服务的 `/design-playground`，通过对应页签或 `?view=<id>` 查看。设计配置面板继续适用于所有模板。

## 当前模板

| ID / 页面             | 适用场景                                     | 推荐 Layout    | 数据与交互                                                                                                                                            |
| --------------------- | -------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| list / 通用列表页     | 无统计卡片的标准业务列表，以通用项目数据演示 | standard-admin | 独立多条件筛选、名称 / 编号 / 负责人、类型 / 团队 / 状态和创建日期范围筛选、待处理过滤、排序分页、固定首列与右侧操作列、本地详情 / 新增 / 编辑 / 删除 |
| data / Dashboard      | 项目、用户、资源等管理列表                   | standard-admin | 固定指标、搜索 / 状态过滤、排序分页、本地新增编辑、归档确认、空状态                                                                                   |
| monitoring / 工业监测 | 设备运维、采集监测、运行状态                 | monitoring     | 固定设备列表、带单位 / 阈值 / 图例的 SVG 趋势、告警；刷新只更新本地示例                                                                               |
| workspace / AI 工作台 | 知识工作区、任务结果与资源组织               | workspace      | 静态内容、结果清单和工具 / 资源面板，不连接 AI、不提供对话能力                                                                                        |

模板分别复用现有 DataManagement.js、ListPage/index.js、Monitoring.js、Workspace.js，`gallery/previews/PagePreviews.js` 只适配布局上下文。它们是设计参考，尚不是特定业务的后端、权限或数据协议实现。

## 使用模板开发

选择与场景相符的信息架构，复用对应公共组件及同一内容实现；不要机械保留示例文案、业务状态、固定日期或统计数字。正式页面采用已有固定 Layout，配套真实 API / Redux / 权限；视图与数据适配分离，让需要的示例继续能用静态数据预览。

PageGallery 外层已经使用 PageLayout，Preview 不再挂载顶部栏与侧栏。推荐 layout 是元数据，不会强制修改独立的用户布局选择。正式页面自带 Layout 时，提取可共享的内容组件供双方引用，不嵌套两套 Shell。

## 新增模板

新增 Dashboard、Detail Page、Form Page、Analytics 等模板时，先确定可复用价值；不预建没有实现的分类。

创建内容组件与静态 Preview，在 page-registry.js 注册 id、name、category、description、tags、layout、preview，再在本文表格中记录用途、状态与数据范围。完整代码示例和命令见 [Page Registry 注册方法](design-playground.md#page-registry新增通用页面模板)。组件层面的资产同步见 [Component Development](ai-design/component-development.md)。

验证独立深链、真实交互、切换布局时不重复导航、浅深色、密度、响应式与生产隔离。生产组件不能反向导入开发注册表；普通业务页面无需注册。

## 通用列表页复用

入口为 `?view=list`。参考经典管理后台列表：上方独立筛选面板，下方列表标题 / 新增、全宽表格与分页，不混入 Dashboard 统计卡片。窄屏仅表格横向滚动；手机竖屏（视口宽度小于 768px 且为竖向）时首列随表格滚动，其他情况下固定首列。右侧操作列始终固定；过滤字段自动换行。

`ListPage/index.js` 组织交互，data.js 提供 32 条独立的通用项目记录和筛选函数，ProjectEditor.js 提供编辑表单。替换字段、列定义和数据适配即可用于其他业务；参考图片仅用于页面结构与布局，不复用其中的业务字段、行业数据、品牌或配色。模板沿用现有 Layout 与三套主题，详情、编辑、删除只修改本地预览，刷新恢复。

表格额外提供项目编号、优先级、完成进度、创建日期、截止日期和备注，便于查看中间列的横向滚动效果；首尾列使用不透明背景。

DataTable 支持 className 调整表格最小宽度，列 className / headerClassName 适配宽度、固定操作列与不透明背景。固定列应同时设置表头和单元格样式，不能让整个页面跟着横向滚动。正式接口接入时保留输入草稿与提交查询的区分、筛选和每页数量变化回到第 1 页、删除后的有效页码以及 pending / 失败反馈。

筛选条件点击搜索后统一生效；创建日期范围包含起止当天，开始晚于结束时保留原查询并提示错误。重置会清空所有筛选并回到第 1 页。

通用列表页是设计系统默认页签。视口小于 768px，或设备采用无悬停的粗指针触屏交互时，默认仅显示项目名称与搜索 / 重置，其他条件通过“展开筛选”显示，隐藏时保留输入；成功搜索或重置后自动收起。已应用的高级条件数显示在展开按钮上。手机横竖屏均保持紧凑交互。每行操作收进“更多操作”图标菜单，操作列缩窄；桌面仍直接显示详情、编辑、删除。仅手机竖屏取消首列固定，横屏、平板与桌面保持固定；右侧操作列始终固定。
