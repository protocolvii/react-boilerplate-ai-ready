# AI Design Guidelines

本说明适用于 Codex、Claude Code、Cursor 和其他能读取项目文件的 AI Agent。项目提供规范、组件、页面模板和开发预览；Agent 根据用户自然语言要求执行设计与开发。脚手架不选择 Agent、不调用 AI，也不控制用户的设计顺序。

## 根据用户目标选择能力

| 能力                   | 用户意图示例                     | 详细规则                                             | 交付物                                        |
| ---------------------- | -------------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| Image Design           | “给设备监测后台出几版设计图”     | [图片设计](ai-design/image-design.md)                | 图片、方案说明；无图像工具则提供提示词        |
| HTML / React Prototype | “直接做一个能点击的用户管理原型” | [原型](ai-design/html-prototype.md)                  | 可在当前开发服务运行的页面和必要交互          |
| Design to Code         | “照这张截图实现界面”             | [设计转代码](ai-design/design-to-code.md)            | 对应的 React 页面、组件映射与视觉验证         |
| Component Development  | “新增通用筛选栏 / 开发业务页面”  | [组件与业务开发](ai-design/component-development.md) | 可复用组件或业务模块，以及适用的 Gallery 示例 |

四种能力独立，不要求先图片、再原型、再业务。可从任意一种开始，也可在已有代码上直接改风格；只读取任务需要的详细规范，不生成未被要求的多套产物。

## 共同约束

先读 [AGENTS.md](../AGENTS.md)、[设计系统](design-system.md)，检查当前 Design Profile、目标模块、组件 API 和 Token 源码。当前工程是 React + JavaScript，业务 `.js` 支持 JSX，官方 shadcn/ui 文件 `.jsx`，不引入 TypeScript。

用户已经确认的视觉方向优先于默认预设；不要在未要求时重做品牌、换主题或调整全局变量。新方向可以超出三套预设，但实现时应合理扩展语义 Token，同时保持状态含义、可访问性和工程一致性。

优先复用现有 Layout、shadcn/ui 和公共组件。业务颜色、字体、边界与节奏遵循 Token；不要复制一套主题组件或大量硬编码样式。真实 API 与 Redux 规则见 [业务开发指南](development.md)。

## 产物与复用

| 产物              | 用途                                           | 转入正式开发时                                     |
| ----------------- | ---------------------------------------------- | -------------------------------------------------- |
| 图片设计稿        | 表达视觉方向与信息层级                         | 仍需组件映射、交互和工程实现，不能称为页面开发完成 |
| HTML / React 原型 | 验证结构、样式和必要交互，可用静态 / Mock 数据 | 优先沿用原代码、提取组件，将数据适配与视图分离     |
| 正式业务页面      | 接入实际接口、权限和状态管理                   | 复用公共组件；有通用价值的模板进入 Page Gallery    |

同一页面不要长期维护两份独立视觉实现。Gallery 尽量引用正式页面使用的同一内容组件，通过预览适配层提供静态数据或回调；不把整个真实业务模块和有副作用的请求直接搬入 Gallery。

新公共组件同步 Component Gallery，新通用页面模板同步 Page Gallery；临时和一次性内部实现不强制收录。注册步骤见 [Design Playground](design-playground.md)，已有模板见 [page-templates.md](page-templates.md)。

## 评审与反馈

用户在 Playground 手动微调后，可导出 JSON 或“复制给 AI Agent”。这些值是按预设 / 实际颜色模式 / 密度分组的覆盖，不是完整主题，也没有写入源码。Agent 检查目标语义与浅深色配对后再修改源文件；清除相应手动覆盖后验证 HMR 的真实代码效果。

交付说明实现与用户意图的映射、复用的组件和 Token、数据是静态/Mock/真实接口、实际浏览器验证、已知限制。没有图片工具、浏览器或后端时明确相应边界，不伪造截图或验证结果。

## 不同 Agent 的入口

AGENTS.md 是共同总入口，README 提供文档索引。本次不新增 CLAUDE.md 或 Cursor Rules。若当前工具不自动发现 AGENTS.md，让用户或项目入口引用它，再读取本任务对应文档；未来工具专用入口也只需引用这套规范，不复制出多份规则。
