# Design to Code

适用于用户提供截图、图片或其他视觉参考并要求实现。可以直接进入本能力，不要求先生成第二份图片或 HTML 原型。通用约束见 [AI Design Guidelines](../ai-design-guidelines.md)。

## 视觉分析

先查看实际参考图，辨认导航、Header、主内容与辅助面板；拆分卡片、列表、表格、表单、图表和操作区。分析颜色语义、字号层级、对齐、间距、圆角与阴影，区分必须保留的视觉意图和纯装饰。

参考图没给出的交互、响应式、权限与数据规则不能视为已有需求。关键不确定点简短澄清，其他合理假设在交付中说明；不要声称知道截图中不可见的业务行为。

## 工程映射

| 参考区域           | 优先映射                                                         |
| ------------------ | ---------------------------------------------------------------- |
| 顶部、侧栏、面包屑 | 现有 Layout、MainHeader / MainMenu、PageHeader                   |
| 指标与状态         | MetricCard、StatusIndicator、语义状态 Token                      |
| 检索和数据列表     | SearchToolbar、FilterBar、DataTable、Pagination                  |
| 表单与确认操作     | 原生 form、shadcn Input / Label、Dialog、ConfirmDialog           |
| 特殊视觉语言       | 对应预设的语义 Token；必要时合理扩展，不能把截图颜色散落到各页面 |

检查已有组件 API 与 [注册表](../design-playground.md)。不能为了贴近截图引入另一套组件库、重写基础组件功能或复刻一套 Sidebar。已有 Token 不合适时，说明影响并在合适层级调整浅深色配对，不擅自改变用户已确认的全局风格。

## 实现与视觉验证

使用当前 JavaScript 文件约定和业务结构，保留原图核心布局与信息优先级，完成合理交互、响应式、可访问性和状态反馈。无需盲目逐像素复制；图片与实际字体、屏幕尺寸不同，差异应有可解释的依据。

用实际业务页面和 Playground 检查实现，不只看代码。至少对比主要对齐、尺寸层级、颜色、留白、表格 / 表单状态、移动端和浅深色。截图验证时说明视口与数据范围；无法使用浏览器时明确未验证项。

复用组件和页面模板按 [组件开发](component-development.md)、[页面模板](../page-templates.md) 同步 Gallery。图片本身不等于完成工程；交付实际访问路径、映射说明与真实验证结果。
