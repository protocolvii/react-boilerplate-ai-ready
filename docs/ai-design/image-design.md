# Image Design

适用于用户要求界面设计图片、视觉草案或多个方向的任务。共同工程约束见 [AI Design Guidelines](../ai-design-guidelines.md) 和 [设计系统](../design-system.md)。这不是业务开发的前置步骤。

## 从自然语言理解需求

分析产品类型、目标用户、主要业务场景、页面用途、核心信息、信息优先级与目标设备。先利用用户已经给出的背景、现有页面和项目资产，不要求固定需求表。对影响方案的缺失信息简短澄清；可合理决定的尺寸、示例数据等说明假设后推进。

尊重已确认的 Design Profile。Modern SaaS 可用于知识库、ERP / CRM；Industrial Pro 强调采集状态、阈值、趋势与运维；Creative AI 适合工具、结果与上下文协作。它们是参考，不限制新的视觉方向。用户只要求单页设计时，不顺带改变全站风格。

## 图片内容与可实现性

- 明确画布，如 1440 × 1000 桌面界面；需要手机稿时单独说明 390px 宽，不把桌面简单缩小。
- 优先展示完整应用界面，说明 Sidebar / Header / Main Content / 辅助面板的结构；采用克制、清楚的信息层级。
- 使用合理的中文标题、字段、单位和示例数据。工业状态需标签、图标和阈值；不堆砌无意义文字或假装真实业务数据。
- 颜色、字体、圆角、阴影与间距保持一致。避免难以工程实现的光效、无功能装饰、大面积玻璃与无意义渐变。
- 考虑 React、shadcn/ui、Lucide 与现有布局的实现方式，说明关键区域可能对应的组件。
- 图片中的文字与图表是设计表达，不代替可访问性、数据精度与实际交互的验证。

## 多方案

用户指定数量时遵循数量；用户要求多个方向但未指定时，可提供 4–8 个有实质差异的方案。差异可以来自导航结构、主次信息、密度、排版、颜色、面板组织和视觉定位，不只是换 primary。每个方向说明适用场景、关键区别和实现取舍。

## 工具与交付

使用当前 Agent 实际拥有的图像工具；脚手架不调用图像服务。如果没有图像能力，明确未生成图片，并提供可以直接使用的提示词，不能把 HTML 截图描述成已生成的设计图。

提示词至少包含：产品与用户、页面目标、业务内容、画布尺寸、布局结构、视觉方向、语言、Token 风格参考、避免项。输出图片或提示词及简短说明即可，不自动生成 React 原型或接入业务 API。用户要求实现时再按 [Design to Code](design-to-code.md) 映射到工程。
